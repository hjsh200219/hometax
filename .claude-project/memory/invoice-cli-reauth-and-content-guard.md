# CLI 발행 재인증과 내용 중복 방지

2026-09-12 외부 보고서 F02/F03 수정.

- 저장된 조회 세션은 signing_certificate_fingerprint를 신뢰할 수 있게 복원하지 않는다.
  CLI --yes 발행·정정·취소는 사용자가 선택한 인증서로 한 번 새 로그인한 뒤 preview/submit.
- 신규 발행에서 ID를 생략하면 검증된 요청 내용을 정규화하여 UUIDv5로 결정한다.
  Decimal 표기 차이·필드 순서는 ID를 바꾸지 않고, 인증서/비밀번호/쿠키는 ID 입력에서 제외한다.
- 주 저널 키(사업자 범위+reference)는 완료 중복을 막는다. 추가 내용 가드(사업자 범위+요청내용)는
  다른 reference의 in_flight/unknown 요청도 막는다. 두 기록은 하나의 BEGIN IMMEDIATE 안에서 저장.
- write_journal v2는 write_guards를 추가한다. v1 기존 행을 변경/삭제하지 않는다.
  내용 가드가 없는 기존 미확정 행이 있으면 신규 발행을 차단한다. 자동으로 재전송하거나
  저널을 지워 해결하지 않는다. 완료된 별개 거래만 명시적 새 ID로 구분한다.
- 보안 보고서의 cryptography 항목 대응: 50.0.1로 갱신, 기존 SEED·PFX·XML 서명 회귀 검증.
- 실제 세무 문서 발행 호환성은 모의 테스트 통과만으로 확정하지 않는다.
